# RecoverAI 🔄⚡

**AI-Powered Revenue Recovery Engine** — Built for the Razorpay AI Buildathon 2026 (AI Revenue Recovery Track)

RecoverAI is an intelligent revenue recovery system that detects failed/at-risk payments, diagnoses root causes using AI, recommends recovery interventions, and enforces deterministic safety policies before executing simulated recovery actions. Recovered outcomes are benchmarked against an independent synthetic ground-truth dataset.

---

> ### ⚠️ Regulatory & Operational Boundaries
> - **Synthetic Payment Data**: All transactions, customer IDs, and failure reasons in this project are synthetically generated.
> - **Synthetic Ground-Truth Benchmark**: Benchmark metrics evaluate recovery accuracy against independent synthetic rules that the LLM never sees. No empirical ground truth or live payment data is used.
> - **Simulated Actions**: Recovery interventions (retries, payment links, reminders) are simulated deterministically using SHA-256 PRNG seeds. **No real monetary movement or live banking interaction occurs.**
> - **Advisory AI**: Google Gemini is used strictly as an advisory diagnostic classifier for the live AI path. It is **never** authoritative for monetary limits, retry limits, permissions, or safety policy enforcement.
> - **Deterministic Policy Control**: Financial safety rules are pure, deterministic code functions that gate and can override all AI suggestions.
> - **Heuristic Fallback**: A deterministic rule-based fallback exists for offline execution and rate-limit resilience.
> - **No Real Conversion Claims**: We do not claim real Razorpay conversion rates, production financial guarantees, or empirical banking performance.

## 1. End-to-End Workflow

```
FAILED / AT-RISK PAYMENT
        ↓
DETERMINISTIC PRE-SCREEN (Filter non-actionable cases)
        ↓
AI ROOT-CAUSE DIAGNOSIS (Gemini 3.5 Flash or Heuristic Fallback)
        ↓
AI RECOVERY RECOMMENDATION (retry, link, reminder, alternate method, escalate)
        ↓
DETERMINISTIC POLICY GATE (8 Safety Rules: limits, thresholds, contact checks)
        ↓
DECISION: APPROVE / BLOCK / HUMAN ESCALATION
        ↓
STABLE RECOVERY SIMULATION (SHA-256 seeded execution)
        ↓
MEASURED OUTCOME & GROUND TRUTH BENCHMARKING
        ↓
IMMUTABLE AUDIT TRAIL
```

## 3. Deterministic Safety Policies (Policy Engine)

The deterministic policy engine enforces 8 safety rules in order of priority:

| # | Rule Name | Trigger Condition | Policy Decision |
|---|-----------|-------------------|-----------------|
| 1 | `max_retry_exceeded` | `payment.retry_count >= 3` and action is `retry_payment` | **BLOCKED** |
| 2 | `high_value_human_review` | `payment.amount > ₹50,00,000` (₹50,000) and action not already escalated | **ESCALATED** |
| 3 | `low_confidence_escalate` | AI self-reported confidence < 0.60 | **ESCALATED** |
| 4 | `repeated_customer_failure` | `customer.previous_failures >= 5` and action is `retry_payment` | **BLOCKED** |
| 5 | `invalid_action_for_reason` | Action is `retry_payment` on `card_expired`, `account_closed`, or `fraud_suspected` | **BLOCKED** |
| 6 | `missing_contact_info` | Action is `send_payment_link` or `send_reminder` but `customer_email` is missing | **BLOCKED** |
| 7 | `subscription_cancelled` | Subscription cancelled by customer | **BLOCKED** |
| 8 | `amount_cap` | `payment.amount > ₹1,00,00,000` (₹1,00,000) auto-recovery cap | **ESCALATED** |

## 4. Evaluation Metrics & Terminology

The evaluation engine computes both **Full Pipeline Metrics** (composite of all processed records) and **Gemini LLM Metrics** (isolated strictly to records generated by the live LLM):

### Synthetic Ground-Truth Benchmark Metrics:
- **Total Revenue at Risk**: $\sum \text{amount}$ of all analyzed failed payments.
- **Ground-Truth Recoverable Revenue**: $\sum \text{amount}$ where `ground_truth_recoverable == true`.
- **AI Predicted Recoverable Revenue**: $\sum \text{amount}$ where AI `is_recoverable == true`.
- **Recovered Revenue**: $\sum \text{amount}$ successfully recovered in simulation.
- **Recovery Rate**: $\frac{\text{Recovered Revenue}}{\text{Total Revenue at Risk}} \times 100$.
- **Recovery Efficiency**: $\frac{\text{Recovered Revenue}}{\text{Ground-Truth Recoverable Revenue}} \times 100$.
- **Approved Action Success Rate**: Percentage of policy-approved actions that succeed.
- **Policy Block Rate**: Percentage of actions safely blocked by policy gates.
- **Escalation Rate**: Percentage of actions routed to human review.

### Classification & Diagnostic Metrics:
- **AI Recoverability Precision**: True Positive rate of recoverability classification against ground truth.
- **AI Recoverability Recall**: Coverage of truly recoverable payments identified by the pipeline.
- **AI Recoverability F1**: Harmonic mean of recoverability precision and recall.
- **Intervention Accuracy**: Percentage of recommended actions matching the ground-truth optimal action.

## 6. Deterministic Demo Scenarios

The system includes 5 guaranteed demo cases to showcase compliance and safety:

- **Case A (`pay_demo_happy_path`)**: Transient UPI timeout → AI recommends `retry_payment` → Policy **APPROVED** → Simulator **SUCCESS** (₹500 recovered).
- **Case B (`pay_demo_max_retries`)**: Retries exhausted (count=4) → AI recommends `retry_payment` → Policy **BLOCKED** (`max_retry_exceeded`).
- **Case C (`pay_demo_high_value`)**: High amount (₹75,000) → AI recommends action → Policy **ESCALATED** (`high_value_human_review`).
- **Case D (`pay_demo_no_email`)**: Card expired, no email → AI recommends `send_payment_link` → Policy **BLOCKED** (`missing_contact_info`).
- **Case E (`pay_demo_low_conf`)**: Uncertain failure cause → AI confidence 0.45 (< 0.60) → Policy **ESCALATED** (`low_confidence_escalate`).

## 7. Quick Start

### Prerequisites
- Python 3.11+
- Node.js 18+
- Google AI Studio API key ([aistudio.google.com](https://aistudio.google.com/apikey))

### Environment Setup

```bash
# Clone and enter repo
cd RecoverAI

# Copy environment template
cp .env.example .env
# Set RECOVERAI_GEMINI_API_KEY in .env (if left blank, deterministic heuristic engine is used)
```

### Backend

```bash
cd backend
pip install -e ".[dev]"
python3 -m pytest tests/ -v          # Run full 57-test suite
python3 -m uvicorn app.main:app --port 8000 --reload
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:5173` to explore the dashboard.

- `test_simulation.py`: SHA-256 reproducibility, physical consistency, and `recovered_revenue <= GT_pool` invariant.
